# AI-assisted closing

This mode takes precedence over the opening-specific equal-size, leverage-target and reference-price rules in SKILL.md. All common browser identity, origin, no-signing and no-submission rules still apply. Read the selected venue sections in [venue checks](venues.md) and the shared Reliable form interaction section in [SKILL.md](../SKILL.md) before interacting; these apply to closing as well as opening.

Require the latest Dashboard `browser-close-v1` instruction with `operation: close`, `action: fill-only`, `network: mainnet`, `scope: entire-account-market-position`, `instructionId`, `recordId`, an unexpired `expiresAt`, and exactly two account-market legs. Require each leg's exact account/owner/subaccount, native perpetual market, base asset, `quantityStep`, `priceTick`, `signedPosition`, `observedAt`, boolean `skip`, `orderType: market`, `reduceOnly: true`, and integer `slippageBps` from 1 to 500. Validate decimal quantities exactly, without floating-point rounding. Reject missing or contradictory data and request a fresh Dashboard preview.

- The signed position is the latest Dashboard snapshot. Positive positions close with sell; negative positions close with buy. For a nonzero leg, `quantity` must equal its absolute signed position and satisfy its base quantity step exactly. Unequal quantities are expected after partial fills; never use original opening quantities, USD sizing, leverage multiplication or a new price to calculate closing quantities.
- A zero leg must have `skip: true` and zero quantity; leave its venue form untouched. Nonzero legs require `skip: false`. If both are zero, no forms are needed: hand back to Dashboard for fresh verification and explicit record closure.
- Use two separate tabs in the same existing Chrome window, never split view. Verify both exact mainnet identities and markets, including skipped legs. Read the actual signed position on each venue and compare it exactly with `signedPosition` before filling. If exposure differs, including an already-closed leg, stop and request a new Dashboard preview. Do not adapt quantities yourself.
- Select the closing side, Market and Reduce-only. Set exact order-form maximum slippage to `slippageBps / 100` percent. Read back all fields after filling, including visibly enabled Reduce-only and base amount units. If Reduce-only or exact slippage is unavailable, if controls can submit on change, or if a close-position button is ambiguous, stop. No Limit/IOC fallback or unbounded substitute.
- Never adjust leverage, margin mode, collateral, account-wide settings or safety protections in closing mode. Never submit, press Enter, sign, connect/authorize a wallet, enable trading or directly call trading APIs. Stop at any such requirement and hand control to the user.
- Expiry applies throughout preparation and readback. New previews replace all older instructions; clear/replace prior non-submitted values only in the intended non-skipped forms. Do not retry uncertain interactions or submissions. A confirmed field-only no-op may be corrected only under the shared form-interaction rules and the user's stopping constraints. If the user explicitly authorizes a retry after a stop, reverify the current instruction expiry, selected identity, market and signed position before resuming; never treat retry authorization as permission to submit or to reuse an expired preview.

Return a checklist of each verified account/subaccount, market, observed signed position, closing side and exact base quantity (or skipped-flat), Market, Reduce-only and exact slippage. State **Forms prepared; no orders submitted by this skill** only when true. Hand control back. The user submits independently, then refreshes Dashboard and explicitly closes the record only after both markets read zero. Partial fills, one-sided exposure and unavailable reads leave the record open. Never call Dashboard association or record-closing APIs on the user's behalf. Snapshots do not establish closing prices, fees, funding or final PnL.
